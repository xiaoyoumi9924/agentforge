# 大作业：十选一

课程给了十个题目，任选其一，也可以自选一个有意义的功能增强。我们选了**第八个：Web UI 后端**。

题目原文（已去掉报名、提交、验收那些前置说明，只留题目）：[`大作业-题目.pdf`](大作业-题目.pdf)

| # | 题目 | 一句话 | 我们为什么不选 |
|---|---|---|---|
| 一 | 并行子代理（Fan-out） | 一次派 N 个子代理并发跑 | 要改线程模型和成本记账，风险最大 |
| 二 | L3 真实检索（混合检索） | 向量 + PageRank + 精确匹配融合 | 要引入嵌入模型和向量库，离「P0 能跑」太远 |
| 三 | MCP 支持 | 让模型直接调用 MCP server | 协议新、资料少，验收标准里要接现成 server |
| 四 | 完整 Tree-sitter 降级链 | 修掉词法索引的误报 | 收益在准确率，演示时看不见 |
| 五 | 真实 tokenizer + 预算预测 | 用真 tokenizer 算预算 | 依赖外部模型文件，可复现性差 |
| 六 | Git Worktree 隔离的子代理 | 每个子代理一个工作树 | 和一、有重叠，且依赖 git 状态 |
| 七 | 完整 gitignore 语法 | 索引时正确跳过被忽略的文件 | 纯工程细节，讲不出故事 |
| **八** | **Web UI 后端** | 浏览器里对话、看工具卡片、点权限 | ✅ **选了** |
| 九 | 自动记忆写入策略 | 让 Agent 自己决定记什么 | 效果难量化，验收标准模糊 |
| 十 | 权限门「记住选择」 | 同一次会话内不再重复问 | 改动太小，撑不起一个作业 |

## 为什么是第八个

1. **唯一能「给人看」的题目。** 其它九个的验收都在终端里、在 trace 里、在分数里；第八个浏览器一开就能演示。
2. **风险可控。** 契约是 `Renderer` 接口，题目只要求「加一个实现」，不要求改核心——`AgentLoop`、`ToolRegistry`、上下文预算一行都不用动。
3. **验收标准最硬。** 五个功能点里有两个是双向通信（权限弹窗、降级），边界情况天然多，20 条自检写得出来。

## 如果重来

会先做**题目三（MCP）**。理由：MCP 是 2025 年的事实标准，做完之后这个 Agent 能接的工具从「自己写的几个」变成「整个生态」，比多一个前端更有长期价值。第八题赢在演示，输在深度。

## 我们的解法

[`08-web-ui/`](08-web-ui) —— 浏览器端完整实现：

- WebSocket 服务端、事件编码、单页前端（编译进 exe，零外部文件）
- 权限弹窗双向：浏览器点「允许」→ 回传 → 唤醒 Agent 线程
- 三层降级：端口被占 / 等不到浏览器 / 运行中掉线，都退回终端
- 新增 20 条自检（I-95 ~ I-105b），全量 115 项通过
