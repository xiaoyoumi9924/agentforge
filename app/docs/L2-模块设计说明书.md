## 1. 引言

### 1.1 编写目的

规定各模块职责边界、对外接口、允许依赖的对象，以及跨模块共享的类型与不变式。
实现人员据此可确定：代码归属、依赖方向、接口输入输出类型、失败表达方式。

### 1.2 三条契约规矩（全文准则）

1. **只加不改**：扩展已有接口靠新增函数/新增结构；破坏兼容必须升版本并评审；
2. **失败即数据**：模块内部错误以返回值/observation 表达，不跨模块抛异常中断流程；
3. **零依赖契约层**：`types.hpp` 不依赖任何项目内文件，被所有模块依赖。

### 1.3 契约思想

- **端口-适配器**：核心层定义抽象（端口），外部实体（厂商 API、WinHTTP、UI、插件）用适配器实现；
- **契约级伪码**：接口定义以"中文描述 + 类 C 结构"表达接口形状与不变式，不表达完整算法；
- **机械可验证**：能用 `static_assert` 或自检程序验证的不变式，必须被验证。

## 2. 契约层（14 项之一）

### 2.1 types.hpp —— 全项目共享类型

**职责**：提供唯一共享词汇表（Message、ChatRequest、ChatResponse、ToolCall、ToolResult、
Usage、RiskLevel、ChatChunk 等）。此文件**不依赖任何项目内文件**（R3）。

**关键决策**：
| 决策 | 理由 |
|---|---|
| `ChatChunk` 用 `std::variant` | 强迫调用方穷尽处理所有事件类型（编译期防遗漏） |
| `Turn` 定义在 types.hpp | 避免 agent_loop ↔ context_budget 循环依赖 |
| `Message` 值语义（无虚函数） | 高频拷贝场景，虚函数×拷贝=性能灾难 |
| `sanitizeUtf8` / `isValidUtf8` 内联于此 | 所有外部字节（argv/文件/命令输出）进入上下文前的统一边界 |

**不变式**：
- INV-T1：非法 UTF-8 经 `sanitizeUtf8` 后必定合法；合法内容不改动（幂等）；
- INV-T2：`RiskLevel` 单调：Read(0) < Write(1) < Exec(2) < Network(3)，权限判定依赖该单调序。

### 2.2 端口清单

| 端口 | 文件 | 方法签名（摘要） | 适配器 |
|---|---|---|---|
| ① 模型 `IModelProvider` | `model_provider.hpp` | `id()`, `contextWindow()`, `supportsTools()`, `chat()`, `stream(onChunk)`, `countTokens()` | `OpenAIProvider`（L3） |
| ② 传输 `IHttpTransport` | `http_transport.hpp` | `post(spec&, body&)`、`postStream(spec&, onData)` | `WinHttpTransport`（L3） |
| ③ 工具 `ITool`（注册表） | `tool_registry.hpp` | `registerTool`, `defs()`, `dispatch(call, ui)`, `invoke(entry, args)` | 内置函数 + C ABI 插件（L4） |
| ④ UI `IUIPort` | `tool_registry.hpp` | `confirm(prompt)`, `notice(msg)` | CLI / `NoUI`（fail-closed） |
| ⑤ 权限 `IPermissionGate` | `tool_registry.hpp` | `evaluate(tool, args)` → `Decision{Allow,Ask,Deny}` | `DefaultPermissionGate`（L4） |
| ⑥ 插件 `IToolPlugin` | `plugin.hpp` | C ABI：`abiVersion`、`execute(argsJson, errOut)`、`freeString` | `sample_plugin`（L4） |
| ⑦ 沙箱 `ISandbox` | `sandbox.hpp` | 受限执行封装（写目录白名单等） | Job Object（L6+） |

### 2.3 核心不变式（契约级）

| 编号 | 不变式 | 落点 |
|---|---|---|
| INV-1 | 每条 tool 消息必须紧跟"请求其 id 的 assistant 消息"，且不被其它消息隔开 | ⑦ 循环 / 消息守卫（L5） |
| INV-2 | `arguments` 序列化为 **JSON 字符串**（非对象） | ② 适配器序列化 |
| INV-3 | 流式只在**首 token 之前**重试；已吐 token 后重试=重复计费+重复内容 | ① 适配器 |
| INV-4 | 权限判定 deny 永远赢（deny 规则强制排最前） | ⑤ 权限门 |
| INV-5 | 无 UI / 无规则时默认拒绝（fail-closed） | ④ ⑤ |
| INV-6 | 大工具结果落盘，上下文只留预览+路径；Read 工具豁免落盘（防"读→落盘→再读"死循环） | ③ 工具 |
| INV-7 | 上下文顺序即缓存前缀：稳定内容（system/tools）固定最前，用户输入恒在最后 | ④ 组装 |

### 2.4 模块职责边界（13 模块）

| 编号 | 模块 | 职责 | 不做什么 |
|---|---|---|---|
| ① | 核心框架与插件管理 | IPlugin 接口、发现/加载/生命周期、注册表 | 不执行业务逻辑 |

| ⑥ | 工具调用与执行环境 | 工具注册表、执行、输出过滤、落盘 | 不决定权限 |
| ⑦ | Agent 循环与任务协调 | 多步循环、任务分解、错误回喂、轨迹 | 不直接碰文件系统 |

## 3. 模块间依赖与数据流

### 3.1 依赖方向（单向）

```
⑪ UI ──▶ ⑦ 循环 ──▶ ② 模型适配 ──▶ ②传输 WinHTTP
   │        │
   │        ├──▶ ⑥ 工具注册表 ──▶ ⑧ 权限门 ──▶ 沙箱
   │        │                    └──▶ ① 插件宿主
   │        └──▶ ④ 上下文组装 ──▶ ③ 索引 / ⑤ 状态
   │                             └──▶ ⑫ 持久化
   └── ⑨ 日志 / ⑩ 配置 / ⑬ 测试（横切，谁都可依赖的底座）
```

### 3.2 一次工具调用循环（L4-L5 目标数据流）

```
for round in 1..N:
  ChatRequest{system, history, tools=registry.defs(), toolChoice=Auto}
  → provider.stream()
  → resp.message.toolCalls?
     是 → for each call: registry.dispatch(call, ui)
          ├─ 查表（未知工具→回喂可用清单）
          ├─ Schema 校验（缺参→回喂"缺少必需字段"）
          ├─ 权限门（deny→拒绝；ask→ui.confirm；拒→fail-closed）
          ├─ invoke（内置函数 / C ABI 插件）
          ├─ sanitizeUtf8 + 大结果落盘过滤
          └─ 生成 tool 消息写回 history
          continue
     否 → finalText = resp.message.content; break
```

## 4. 自检设计（contract_check）

`tests/contract_check.cpp` 是本讲唯一可执行物，把"契约自洽"变成可执行判据：

| 检查项 | 判据 | 失败含义 |
|---|---|---|
| 编译期类型关系 | static_assert（Message/Usage/ToolCall 值语义、enum 序） | 类型契约被破坏 |
| 预算分配 | L0–L6 各层配额之和 == 可用量；历史层预算 > 0 | 预算数学错误 |
| RiskLevel 单调 | Read < Write < Exec < Network | 权限判定逻辑错误 |
| 文本卫生 | 合法 UTF-8 识别、GBK 识别为非法、消毒幂等 | 序列化会抛 type_error.316 |
| 主要类型体积 | Message / ToolCall 尺寸合理（拷贝成本可见） | 性能隐患 |

构建与运行：

```powershell
./build.ps1 -Target contract_check
./build/contract_check.exe
```

预期输出全部 `[PASS]`。
