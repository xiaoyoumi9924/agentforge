## 1. 引言

### 1.1 编写目的

规定 AgentForge（Coder 类 AI Agent harness）的功能需求、非功能需求、
设计约束与外部接口需求，作为后续设计、实现与验收的需求依据。

### 1.2 适用范围

覆盖 AgentForge 的**命令行形态**（L1–L5），并预留后续 GUI 形态；
包括任务理解、文件读写、命令执行、多步循环、失败恢复、过程可观察与危险操作控制。
**不覆盖**：模型训练/微调、多智能体协作平台、Web 服务形态、云部署。

### 1.3 读者对象

总体设计人员、模块实现人员、测试与验收人员（小组）、安全评审人员。

### 1.4 参考文献

- 骨架.md —— 13 模块全景与 W1–W4 核心机制
- 课件文档：000 课程简介 / 001 AI 全流程软件工程 / 002 会话流程与缓存 / 003 AgentForge / 004 MockLLM / 010 初识 AI Coding / 020 最小闭环 / L3-v0 / L4-v1 / L5-v2
- OpenAI Chat Completions 协议（含 tools / stream / stream_options）
- Server-Sent Events 规范

### 1.5 术语

| 术语 | 定义 |
|---|---|
| Harness | 围绕模型构建的完整系统：工具、循环、上下文、权限、沙箱 |
| Turn / Step | 一次任务周期 / Turn 内一次模型调用及其工具执行 |
| MockLLM | 模拟大语言模型，按预定义规则返回响应，用于测试与开发 |
| observation | 回喂给模型的工具执行结果（含失败结果） |
| 权限门（Gate） | 应用层执行前授权判定（deny/ask/allow） |
| 沙箱（Sandbox） | 操作系统内核强制访问控制（如 Job Object） |

### 1.6 实施阶段

按课程讲次推进：L1 需求与总体设计 → L2 模块契约 → L3 能对话 →
L4 工具调用 → L5 AgentLoop → 之后逐模块补齐（见 §7 追溯矩阵）。

## 2. 系统概述

### 2.1 产品定位

让模型「看懂代码、修改代码、执行代码」的工作台：模型只产出**意图**，
Harness 负责工具执行、上下文管理、安全边界与过程可观察。

### 2.2 产品目标

1. 最小闭环优先：先跑通「提问 → 流式回答 → 工具调用 → 回喂 → 收尾」；
2. 模块化：13 模块按依赖单向分层，可独立替换（模型、工具、UI）；
3. 安全默认：无确认则拒绝（fail-closed），密钥不落明文；
4. 可观察、可测试：MockLLM + 回归脚本全链路验证。

### 2.3 功能边界

- 仅支持 OpenAI 兼容 Chat Completions 接口（第一版）；
- 不内置仓库索引/向量库（后续版本）；
- 不承诺跨平台（Windows 优先，工具链 MSVC）。

## 3. 功能需求

### FR-1 会话与模型交互

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-1.1 | 支持无状态多轮对话：每次请求携带完整历史（含 system/user/assistant/tool 消息） | 连续两轮对话，第二轮请求含第一轮内容 |
| FR-1.2 | 流式输出：逐 token 渲染（SSE `data:` 分帧，跨块缓存，兼容任意 TCP 切分） | MockLLM 分块返回，UI 边收边显 |
| FR-1.3 | 超时与重试：可配置超时；网络/5xx 错误按策略重试并分类 | 断开服务端可触发重试与明确报错 |
| FR-1.4 | 模型可配置：环境变量 `OPENAI_API_KEY` / `OPENAI_BASE_URL`，不硬编码密钥 | 改环境变量即切换端点 |

### FR-2 工具调用

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-2.1 | 工具以 JSON Schema 声明（name/description/parameters），随请求下发 | 请求 tools 字段存在且顺序稳定 |
| FR-2.2 | 工具注册表：内置工具 + C ABI 插件；未知工具回喂可用工具列表 | 幻觉工具名 → observation 含工具清单，不崩溃 |
| FR-2.3 | 参数校验：必填与类型检查；失败把"缺少必需字段 path"等指导性错误回喂模型 | 缺参调用 → 模型下一轮自行修正 |
| FR-2.4 | 工具执行结果统一回喂：失败也是 observation，不抛异常 | 失败不中断循环 |
| FR-2.5 | 内置四工具（L5 起）：Read / Write / Edit / Bash；Read 豁免大结果落盘 | Read 不触发落盘循环依赖 |
| FR-2.6 | 大结果落盘：超阈值写文件，上下文仅留预览+路径 | 大文件读取后上下文不爆 |

### FR-3 Agent 循环

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-3.1 | 推理→工具调用→观察→再推理，多步直至模型不再请求工具 | 多轮工具链路收敛 |
| FR-3.2 | 循环有上限（防死循环），支持取消/中断 | 达到上限安全终止并说明 |
| FR-3.3 | 每轮把完整 assistant 消息（含 tool_calls）与 tool 结果写回历史 | 下一轮 tool 消息与前一轮 tool_call_id 配对 |
| FR-3.4 | 消息合法性守卫：禁止孤儿 tool、配对窗口被打断、只回一半 | 非法历史被拦截并修复，不产生 400 |
| FR-3.5 | 退出条件：模型不再请求工具 → 输出最终回答并收尾统计 | 无工具调用即结束 |

### FR-4 上下文组装

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-4.1 | 分层组装：系统提示/项目知识/仓库地图/检索命中/活动文件/历史/用户输入 | 顺序固定，用户输入恒在最后 |
| FR-4.2 | token 预算：按比例配额并监控消耗；超预算按降级链压缩（全文→签名→符号名→路径→丢弃） | 超长上下文仍成功完成请求 |
| FR-4.3 | 历史管理：滑动窗口/摘要压缩，压缩不破坏缓存前缀 | 压缩后前缀内容不变 |

### FR-5 仓库理解（后续阶段）

FR-5.1 符号索引与依赖图；FR-5.2 按关键词/路径/符号检索相关片段；
FR-5.3 增量更新。**（L1 不要求实现）**

### FR-6 安全与权限

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-6.1 | 权限门：deny/ask/allow，deny 优先（deny 永远赢） | 规则表 deny 覆盖 allow |
| FR-6.2 | ask 分支阻塞询问，用户拒绝则工具不执行（fail-closed） | 拒绝后插件未被调用 |
| FR-6.3 | 沙箱：内置工具在受限环境执行；写操作限制在工程目录内 | 越界写被拒 |
| FR-6.4 | 密钥安全：API Key 用 Windows DPAPI 加密保存，不落明文 | 配置文件无明文密钥 |
| FR-6.5 | 审计：危险操作（写/执行/网络）记录审计日志 | 审计可追溯 |

### FR-7 会话持久化（后续阶段）

FR-7.1 SQLite 存会话与消息；FR-7.2 会话恢复；FR-7.3 长期记忆。**（L1 不要求）**

### FR-8 可观测性

FR-8.1 结构化日志（时间/级别/模块/事件）；FR-8.2 每 turn 统计 token 用量与延迟；
FR-8.3 请求追踪（trace id）。**（L1：至少统计与本轮打印）**

### FR-9 配置管理

FR-9.1 集中配置（模型、预算比例、权限规则）；FR-9.2 环境变量覆盖；
FR-9.3 配置错误给出明确提示。**（L1：环境变量生效即可）**

### FR-10 插件管理

FR-10.1 C ABI 插件接口（extern "C"、不跨边界抛异常、谁分配谁释放）；
FR-10.2 动态加载（LoadLibrary，中文路径支持）；FR-10.3 生命周期与 ABI 版本校验。
**（L4 起逐步实现）**

### FR-11 用户界面

L1–L4：CLI（UTF-8 控制台，参数编码处理）；
后续：Qt Widgets 对话窗口、diff 查看器、命令面板。**（L11 目标）**

### FR-12 测试与评估

FR-12.1 MockLLM 覆盖上下文组装/工具循环/压缩/流式/边界；
FR-12.2 回归脚本（verify.ps1）自动化验收；FR-12.3 基准评分报告。**（L3 起持续）**

## 4. 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-1 | 首 token 延迟：流式首字尽快出现 | Mock：<1s；真实 API：受网络影响，仅要求流式渲染 |
| NFR-2 | 成本控制：缓存友好结构（稳定内容前缀固定，tools 顺序稳定）；token 用量可见 | 前缀缓存可命中；日志含 usage |
| NFR-3 | 健壮性：工具失败/模型幻觉/非法历史均不崩溃，回喂修复 | verify 全用例 PASS |
| NFR-4 | 安全：fail-closed、最小权限、密钥不落明文 | FR-6 各验收点通过 |
| NFR-5 | 可扩展：替换模型/工具/UI 不改核心；插件热加载 | 新增工具仅注册即可用 |
| NFR-6 | 可移植：Windows 10/11 + MSVC；代码不依赖第三方网络库（WinHTTP） | 干净机器可构建 |
| NFR-7 | 可测试性：MockLLM 可模拟超长输出、错误格式、超时 | 单元/回归测试可跑 |
| NFR-8 | 依赖轻量：JSON 用 nlohmann/json 单头文件（thirdparty，无包管理器） | 构建无需网络 |

## 5. 设计约束与外部接口

### 5.1 平台约束

- OS：Windows 10/11 x64；编译器：MSVC（VS 2022/2026）；
- 构建：`build.ps1` 手动配置 INCLUDE/LIB/PATH 直接调 cl.exe（见总体设计）；
- 源文件一律 UTF-8（无 BOM），编译加 `/utf-8`。

### 5.2 外部接口

1. **模型接口**：OpenAI 兼容 `POST /chat/completions`，支持 `stream: true`、
   `tools`、`tool_choice`、`stream_options.include_usage`；SSE 响应；
2. **密钥**：`OPENAI_API_KEY`（环境变量优先；后续 DPAPI 配置）；
3. **端点**：`OPENAI_BASE_URL`（默认官方；Mock 时指向 `http://127.0.0.1:8789/v1`）；
4. **插件**：C ABI（`AF_PLUGIN_ABI_VERSION`），`LoadLibrary` + ABI 校验。

### 5.3 环境变量清单

| 变量 | 说明 | 默认 |
|---|---|---|
| OPENAI_API_KEY | 模型 API 密钥 | 空 |
| OPENAI_BASE_URL | OpenAI 兼容端点 | 官方默认 |
| AF_MODEL | 模型名 | gpt-4o-mini / mock-1 |
| AF_PLUGIN | 插件 DLL 路径（L4） | 空 |

## 8. 风险与对策（摘要）

| 风险 | 影响 | 对策 |
|---|---|---|
| VS2026 与 MSVC 2022 套件/工具集不匹配 | 构建失败 | 安装 VS 2022 兼容包或换 2022 工具集；构建脚本先试 cl 再报可读错误 |
| 模型幻觉非法参数/工具名 | 循环中断 | observation 回喂 + 工具清单提示 |
| 上下文超预算 | 请求 400 / 费用超支 | 降级链 + 消息守卫 + 预算监控 |
| 中文路径/编码（GBK） | 路径失效、JSON 异常 | 宽字符 API + sanitizeUtf8 + `/utf-8` |
| AI 生成代码缺乏审查 | 质量/责任风险 | 小组逐讲评审验收（人机协同原则） |
