# L3 能对话 —— 设计说明

| 项 | 内容 |
|---|---|
| 阶段 | L3 · v0 能对话 |
| 上游 | SDD（端口① ②、契约层 types.hpp） |
| 代码 | `src/main.cpp`、`src/providers.cpp`、`src/sse_parser.*`、`src/http_winhttp.cpp`、`tests/mock_server.py` |
| 验收 | `tests/verify_L3.ps1` 全 PASS（不需要真 API Key） |

## 1. 本讲目标

最小闭环的第一步：**把一句话发给模型，把流式回答打出来。**
刻意不带 Agent 循环、工具调用、上下文组装（分别是 L5 / L4 / L7）。

## 2. 组件拆分（三层职责）

| 组件 | 职责 | 无关性 |
|---|---|---|
| `SSEParser` | 只负责字节边界：按 `\n\n` 切帧、`data:` 字段提取、跨块缓存 | 不关心 JSON 内容与厂商 |
| `StreamCtx` | 协议翻译 + 状态机：SSE 事件 → `ChatChunk` 语义事件；累积正文/usage/finish_reason | 不关心渲染 |
| `Renderer` | 只负责展示：`std::visit` 穷尽处理 `ChatChunk`，逐 token 打印 flush | 不关心协议 |

**为什么必须有 StreamCtx**：上游（传输层）看到任意切分的字节块，下游（Renderer）看到结构化语义事件，
中间有三重鸿沟（边界/协议/状态）。StreamCtx 是唯一同时知道"字节长什么样"和"语义长什么样"的组件。

## 3. 一次请求的数据流

```
main.cpp: winUtf8Args() → sanitizeUtf8(task)
  → 组装 ChatRequest{system, messages:[user]} → OpenAIProvider::stream
    → toRequest() → JSON（stream:true, stream_options.include_usage）
    → HttpProviderBase::execute → WinHttpTransport::doRequest
      → WinHttpReadData 循环 → onData(buf, len)
        → StreamCtx::feed → SSEParser::push（分帧）→ dispatchOpenAI
          → usage? → UsageChunk；content? → TextDelta；finish_reason? → DoneChunk
          → onChunk(c) → Renderer::operator() → cout << ... << flush
```

## 4. Windows 编码两个真坑（第一天就必须处理）

1. **控制台代码页**：默认 GBK → 中文输出乱码；启动即 `SetConsoleOutputCP(CP_UTF8)`；
2. **argv 编码**：`main()` 拿到的 argv 是 ANSI 代码页字节（中文机=GBK），
   中文任务会让 `json::dump()` 抛 `type_error.316`。修法：`GetCommandLineW()` 取宽字符命令行，
   自己转 UTF-8（`winUtf8Args`）。环境变量同理用 `_wgetenv`。

## 5. 验证用例（verify_L3.ps1）

| 用例 | 目的 | 判据 |
|---|---|---|
| C1 英文提问 | 正常流式 + usage 事件恰好 1 次（带 null 的帧不误判） | exit=0，正文完整，usageEvents=1，finish=0 |
| C2 中文提问 | argv 编码正确 | 中文原样到达服务端并被回显 |
| C3 被截断回答 | finish_reason=length 必须显式报出 | 输出含"被截断"、finish=2 |
| C4 空回答 | 200 但无内容必须判失败而非成功 | exit=2，输出"没有收到任何内容" |

服务端侧断言：无 BAD JSON（编码正确）、model 是真实模型名 mock-1（不是厂商名 openai）、
请求为 stream=True、v0 未下发工具、四个用例都到达服务端。

./build/agent.exe "用一句话解释 SSE"
