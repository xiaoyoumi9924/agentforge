## 1. 六道闸门（LoopLimits）

| 闸门 | 实现 | 行为 |
|---|---|---|
| 1 maxSteps | 循环计数 | 超限 → `StepLimitReached` |
| 2 maxTokensSpent | 每轮 usage 累加 | 超限 → `BudgetExceeded` |
| 3 maxWallClock | steady_clock 计时 | 超时 → `WallClockExceeded` |
| 4 maxConsecutiveErrors | 工具失败连续计数 | 超限 → `TooManyErrors` |
| 5 maxRepeatedCalls | 连续相同 (tool,args) 检测 | 插入提醒（不阻断，L6 语义） |
| 6 用户中断 | `std::stop_token` | 流式回调返回 false 立即中止传输；→ `UserAborted` |

## 2. 沙箱（端口 ③）

`JobObjectSandbox`（Windows Job Object）提供内核层硬边界：

- **进程树强杀**：`KILL_ON_JOB_CLOSE` —— 子进程与父进程同 Job，越权开子进程也同权；
- **资源上限**：活动进程 ≤ 16、内存 ≤ 256MB（防 fork 炸弹/内存炸弹）；
- **超时强杀**：超时后 `TerminateJobObject` 整树杀掉，并**区分"沙箱拦截"与"命令失败"**。

**能力自检（`--sandbox-check`）如实报告**：
```
[OK] 进程树强杀
[OK] 活动进程数上限 = 16
[OK] 内存上限 = 256 MB
[--] 网络隔离：未强制（Job Object 不提供网络拒绝能力，需 AppContainer）
[--] 文件系统单目录写限：未强制（应用层权限门兜底，非内核边界）
```
★ 为什么必须诚实：把"未强制"写成"OK"会让用户把安全边界建立在幻觉上。
这正是课程 ADR-4 的立场：边界要么下沉到内核，要么明说它不在。

## 3. 纵深防御：写路径围栏

Write/Edit 在进入系统调用前做规范化路径检查（工作目录内才允许写）。
**这不是安全边界**，只是把低级越界挡在门口——真正的"该不该做"在权限门。

## 4. 结构化日志（JSON Lines）

一行一个事件：`ts / level / mod / msg / extra`。

- 主路径：`main`（start/done）、`loop`（tool-start/provider-error）、
- 审计（模块 ⑧ 交叉）：`audit`（write/edit/bash/bash-done/bash-blocked/write-rejected）。

环境变量 `AF_LOG` 可改日志路径（默认为 `agentforge.log`）。
