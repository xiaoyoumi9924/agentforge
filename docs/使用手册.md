## 一、安装

### 1.1 环境要求

| 项 | 要求 |
| --- | --- |
| 系统 | Windows 10 1809 及以上 / Windows 11，x64 |
| 权限 | 普通用户即可，**不需要管理员** |
| 运行时 | 无需安装 .NET、Python、VC++ 运行库 |
| 网络 | 能访问 `api.deepseek.com`（或你自选的 OpenAI 兼容端点） |
| 磁盘 | 约 20 MB，另有工作目录占用 |

### 1.2 三种安装方式

三种方式装出来的结果完全一样，都在 `%LOCALAPPDATA%\AgentForge`。

**方式一：PowerShell（推荐）**

```powershell
irm https://raw.githubusercontent.com/xiaoyoumi9924/agentforge/main/install.ps1 | iex
```

**方式二：Git Bash / MSYS / Cygwin**

```bash
curl -fsSL https://raw.githubusercontent.com/xiaoyoumi9924/agentforge/main/install.sh | bash
```

**方式三：手动下载**

到 [Releases 页面](https://github.com/xiaoyoumi9924/agentforge/releases/latest) 下载
`AgentForge-Web-v1.0.0.zip`（1.2 MB），解压到任意目录，双击 `run-web.bat` 即可运行。
手动安装不依赖网络脚本，适合代理环境或内网。

### 1.3 安装脚本做了什么

1. 读取 GitHub Releases，取最新版本的 zip 地址
2. 下载（走系统代理；`Invoke-WebRequest` 失败时回退到 `curl.exe`）
3. 解压到 `%LOCALAPPDATA%\AgentForge`
4. 启动 `run-web.ps1`（工作目录由它创建并切换）

不写注册表、不建快捷方式、不改 `PATH`，因此卸载就是删除目录。

可调参数：

```powershell
# 指定安装目录
.\install.ps1 -Dir D:\Tools\AgentForge

# 指定版本
.\install.ps1 -Version v1.0.0

# 只装不启动
.\install.ps1 -NoStart

# 手动指定代理
.\install.ps1 -Proxy http://127.0.0.1:7890
```

### 1.4 安装目录结构

```
%LOCALAPPDATA%\AgentForge\
├── agent.exe           主程序（约 7 MB，单文件，无外部依赖）
├── run-web.bat         Windows 双击入口
├── run-web.ps1         实际启动脚本
├── key.dat             首次启动后生成，DPAPI 加密的 API Key
├── README.txt          离线说明
└── workspace\
    └── web\            Agent 的工作目录与全部产出
```

### 1.5 验证安装成功

双击 `run-web.bat`，正常情况下会出现：

1. 一个命令行窗口，打印工作目录与所用模型
2. 浏览器自动打开 `http://127.0.0.1:8080`，显示对话界面

命令行窗口**不能关**——它就是服务本体，关掉等于停止服务。

## 二、连接模型

### 2.1 首次启动

`run-web.ps1` 按以下顺序找 API Key：

1. 环境变量 `OPENAI_API_KEY`
2. 同目录下的 `key.dat`
3. 都没有 → 在终端里问你要一次，输入后加密存成 `key.dat`

`key.dat` 由 Windows DPAPI 在当前用户下加密，**换用户或换机器都无法解密**，
所以可以放心留在磁盘上；要换 Key 就删掉它重启。

### 2.2 在网页里改 Key

左下角 **设置 → API Key**，粘贴后保存，**下一条消息**起生效（不必重启）。

网页里填的 Key 存在浏览器 `localStorage`，会随会话传给本地服务；它不会写进仓库或日志。

### 2.3 换端点或换模型

网页设置里只提供 Key，端点和模型由启动环境决定，默认值在 `run-web.ps1` 中：

```powershell
if (-not $env:OPENAI_BASE_URL) { $env:OPENAI_BASE_URL = 'https://api.deepseek.com/v1' }
if (-not $env:AF_MODEL)        { $env:AF_MODEL        = 'deepseek-chat' }
```

因此两种改法：启动前设好同名环境变量，或直接编辑这两行。

| 目标 | `OPENAI_BASE_URL` | `AF_MODEL` |
| --- | --- | --- |
| DeepSeek（默认） | `https://api.deepseek.com/v1` | `deepseek-chat` |
| DeepSeek 推理模型 | `https://api.deepseek.com/v1` | `deepseek-reasoner` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5-coder:14b` |

> 端点必须兼容 OpenAI 的 `chat/completions` 协议，并且**支持 function calling（tools）**。
> 纯文本模型能连上，但用不了工具，也就改不了文件。

## 三、界面与操作

### 3.1 布局

| 区域 | 内容 |
| --- | --- |
| 左栏 | 会话列表、设置入口、收起按钮 |
| 中间 | 消息流：你的指令、Agent 的回复、工具卡片 |
| 底部 | 输入框、权限模式、压缩上下文、发送 |

输入框下方一行状态：`轮`、`步`、`tok`，分别对应当前任务的轮次、工具调用次数与累计 token。

### 3.2 一次任务的过程

1. 输入指令，按 `Enter` 发送（`Shift+Enter` 换行）
2. 模型决定调用哪个工具，界面出现一张工具卡片
3. 卡片显示工具名、参数、耗时与输出；失败时输出里带退出码
4. 反复若干轮后给出结论，本轮结束

工具卡片右侧可展开完整输出；代码块右上角有「复制代码」。

### 3.3 权限模式

输入框上方下拉框，两种模式：

| 模式 | 行为 |
| --- | --- |
| 每次询问权限（默认） | 写文件、执行命令前弹窗，显示工具与参数，点允许才执行 |
| 自动允许（危险） | 不再询问，全部放行 |

弹窗 **30 秒无响应按拒绝处理**（可用 `AF_WEB_PERM_TIMEOUT_MS` 调整），
超时拒绝是刻意的：没有明确批准就不执行。

### 3.4 中断

网页上**没有停止按钮**：任务在本地进程里跑，关掉标签页不会中断它，重新打开地址即可继续查看。

要真正停下，去命令行窗口按 `Ctrl+C`，或直接关闭该窗口。

### 3.5 压缩上下文

任务很长、token 涨得快时，点「压缩上下文」把较早的历史折叠成一份交接摘要，
保留最初需求与读写过的文件路径，腾出窗口给后续步骤。自动压缩在接近预算时也会自行触发。

## 四、怎么写任务

Agent 不会追问澄清，指令含糊它就自己猜，猜错了要花好几轮才能纠回来。一条好指令包含三件事：

1. **目标**：要得到什么结果
2. **输入**：从哪个文件、哪个目录出发
3. **验收**：怎么算做完（跑测试、输出到哪个文件）

| 指令 | 评价 |
| --- | --- |
| 「看看这个项目」 | ✗ 没有目标也没有验收 |
| 「修复 bug」 | ✗ 不说是哪个 bug |
| 「跑一遍 `ctest`，失败用例按报错改到全绿」 | ✓ 有目标有验收 |
| 「读 `data.csv`，按产品汇总销售额写到 `summary.md`，金额保留两位小数」 | ✓ 输入、输出、格式都清楚 |

几条经验：

- 一次只交代一件事，多目标会让它在工具之间反复横跳
- 需要它改代码时，明确说「改完跑一次构建确认」——否则它可能只改不验
- 路径尽量写相对路径，相对的是工作目录 `workspace\web`
- 想要它读仓库结构，先说「先看 `src/` 有哪些文件」比自己描述结构更快

## 五、工作目录与产出

### 5.1 固定目录

不管从桌面、开始菜单还是命令行启动，`run-web.ps1` 都会把工作目录切到
`%LOCALAPPDATA%\AgentForge\workspace\web`。Agent 产生的所有文件都在这里，
不会散落到桌面或下载文件夹。

```
workspace\web\
├── hello.cpp            你让它写的文件
├── summary.md           它汇总的结果
└── ...
```

### 5.2 换工作目录

编辑 `run-web.ps1` 里这一行：

```powershell
$WorkDir = Join-Path $Here 'workspace\web'
```

改成任意绝对路径即可，脚本会自动创建。

### 5.3 相对路径的含义

你在指令里写 `data.csv`，解析出来是 `workspace\web\data.csv`。
要让 Agent 处理其他目录的文件，要么把文件放进来，要么写绝对路径。

## 六、配置项

配置来源三层，后者覆盖前者：**代码默认值 → `af_config.json` → 环境变量**。

### 6.1 环境变量

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 模型密钥 | 无（读 `key.dat`） |
| `OPENAI_BASE_URL` | 端点地址 | `https://api.deepseek.com/v1` |
| `AF_MODEL` | 模型名 | `deepseek-chat` |
| `AF_PROVIDER` | 提供方类型 | `openai` |
| `AF_CONTEXT_WINDOW` | 上下文窗口 token 数 | 按模型 |
| `AF_WEB_PORT` | 网页端口 | `8080` |
| `AF_WEB_PERM_TIMEOUT_MS` | 权限弹窗超时（毫秒），超时即拒绝 | `30000` |
| `AF_WEB_WAIT_MS` | 起服务后等浏览器多久再退回纯终端 | `3000` |
| `AF_WEB_DEBUG` | 设为任意值，把每帧收到的消息打到终端 | 关 |
| `AF_UI` | 界面后端：`web` / `plain` / `auto` | `auto` |
| `AF_LOG` | 日志路径 | `agentforge.log` |
| `AF_SESSION_ID` | 会话 id | `default` |
| `AF_SESSION_DIR` | 会话落盘目录 | 当前目录 |
| `AF_PLUGIN` | 额外加载的 C ABI 插件路径 | 无 |

### 6.2 配置文件

在工作目录放一个 `af_config.json`，缺的字段按默认值处理：

```json
{
  "provider": {
    "kind": "openai",
    "baseUrl": "https://api.deepseek.com/v1",
    "model": "deepseek-chat"
  },
  "budget": {
    "contextWindow": 65536,
    "reserveForReply": 8192,
    "maxOutputTokens": 4096
  },
  "sandbox": {
    "enabled": true,
    "allowNetwork": false
  },
  "sessionId": "default"
}
```

改完重启服务生效。

## 七、命令行

`agent.exe` 不带 `--web` 时是纯终端 Agent，适合脚本化与自动化。

```powershell
agent.exe "读一下 src/ 下所有 TODO，汇总成 todo.md"
```

### 7.1 常用参数

| 参数 | 说明 |
| --- | --- |
| `agent.exe "<任务>"` | 终端里跑一次任务 |
| `--web [任务]` | 起浏览器界面；给任务则先执行，不给则等浏览器输入 |
| `--resume [任务]` | 恢复指定会话继续，会话 id 走 `AF_SESSION_ID` |
| `--sessions` | 列出本地会话 |
| `--session-debug <文件>` | 打印会话文件内容与校验结果 |
| `--selftest` | 115 项进程内自检，不联网、不花钱 |
| `--sandbox-info` | 打印沙箱能力与限制 |
| `--show-repo-map [根目录]` | 打印仓库索引地图 |
| `--symbol-ab [根目录]` | 对比两种符号抽取的效果 |
| `--cost <trace.jsonl>` | 统计一次运行的 token 与费用 |
| `--context [根目录]` | 打印上下文各层占用 |
| `--regress <regress.jsonl>` | 跑回归用例 |
| `--ui-demo [plain\|ftxui]` | 不接模型，单独演示界面渲染 |

### 7.2 典型组合

```powershell
# 换端口起服务
$env:AF_WEB_PORT = 8090
agent.exe --web

# 无窗口脚本化：跑完即退出
$env:OPENAI_API_KEY = "sk-..."
agent.exe "运行 tests 并把失败原因整理成 report.md"

# 先自检，确认环境没问题再干活
agent.exe --selftest
```

## 八、常见问题

### 端口 8080 被占用

换端口：`$env:AF_WEB_PORT = 8090; .\run-web.ps1`，然后访问 `http://127.0.0.1:8090`。

### 浏览器没自动打开

手动访问 `http://127.0.0.1:8080`。若命令行窗口已经退出，说明服务没起来，
重新运行 `run-web.bat` 并看窗口里的报错。

### 页面白屏或一直「等待任务」

先刷新页面（WebSocket 会自动重连）。仍然不行就在启动前设 `$env:AF_WEB_DEBUG = 1`，
终端会打印每个收到的帧，用来判断是后端没发还是前端没渲染。

### 提示没有 API Key / 401 / 余额不足

- 401：Key 错了或过期，删掉 `key.dat` 重启重填
- 402 / Insufficient Balance：账户余额不足
- 模型名写错会返回 404，检查 `AF_MODEL`

### 模型说「我没有工具」或反复读同一个文件

多半是这个模型不支持 function calling，或工具调用格式不兼容。换 `deepseek-chat`、
`gpt-4o-mini` 这类明确支持 tools 的模型。

### 命令被沙箱拦截

沙箱默认禁网、限进程数与内存、超时强杀。被拦时工具结果会写明原因，
重试同样的命令没有意义——需要联网的操作应当由你在本地完成，或调整 `af_config.json` 的
`sandbox.allowNetwork`。

### 下载安装脚本卡住

`raw.githubusercontent.com` 在部分网络下不可达。开代理后重试（脚本读 `HTTPS_PROXY`），
或直接走手动下载：Releases 页面下 zip，解压双击 `run-web.bat`。

### 杀毒软件报毒

`agent.exe` 未做代码签名，且会创建进程执行命令，容易被启发式规则误判。
加白名单即可；源码在 `02-agentforge/`，可自行编译验证。

### 中文路径或中文文件名出问题

程序内部统一按 UTF-8 处理路径与环境变量，但**被调用的第三方命令**仍按系统代码页解释参数。
遇到乱码优先改用英文路径。

## 九、卸载与清理

1. 关闭命令行窗口（服务随之退出）
2. 删除 `%LOCALAPPDATA%\AgentForge`（包含程序、`key.dat` 与全部产出）
3. 浏览器里清除该站点数据，可一并删掉 `localStorage` 中保存的 Key

手动安装的版本，删除解压出来的那个文件夹即可。
