## 1. 设计目标与原则

### 1.1 目标

1. **最小闭环优先**：先打通「用户问 → 模型流式答 → 工具调用 → 观察回喂 → 收敛」；
2. **端口-适配器**：核心层只依赖抽象（IModelProvider / IHttpTransport / IUIPort），
   外部实体（厂商 API、WinHTTP、UI）可替换；
3. **依赖单向**：交互执行层 → 核心智能层 → 基础设施层，禁止逆向依赖；
4. **可机械验证**：契约不变式以 `static_assert` 与自检程序强制。

### 1.2 原则（三条契约规矩）

- **只加不改**：已有接口扩展走新增函数/结构，破坏兼容必须升版本；
- **失败即数据**：错误以 observation 形式回喂模型，不抛异常中断循环；
- **默认拒绝**：安全相关缺省行为为拒绝（无 UI、无规则 → deny）。

## 2. 组织架构与分层

### 2.1 三层 / 13 模块

```
┌──────────────────────────────────────────────────────────────┐
│ 交互执行层  ⑥ 工具调用与执行环境   ⑪ UI 与交互   ⑬ 测试与评估 │
├──────────────────────────────────────────────────────────────┤
│ 核心智能层  ⑦ Agent 循环与任务协调  ② 多模型适配  ④ 上下文组装 │
│             ③ 仓库理解与索引        ⑤ 增量状态管理             │
├──────────────────────────────────────────────────────────────┤
│ 基础设施层  ① 插件管理  ⑧ 安全与权限  ⑨ 可观测性  ⑩ 配置  ⑫ 持久化 │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 依赖规则

| 编号 | 规则 |
|---|---|
| R1 | 交互执行层只能依赖核心智能层；核心智能层只能依赖基础设施层与**端口** |
| R2 | 端口（抽象接口）定义在核心层，适配器（实现）位于外层或独立实现文件 |
| R3 | 契约层 `types.hpp` 不依赖任何项目内文件（零依赖） |

### 2.3 跨模块核心机制（W1–W4）

| 机制 | 定义 | 落点 |
|---|---|---|
| W1 上下文闭环 | 索引→检索→组装→更新→压缩 | ③④⑤ |
| W2 Agent 循环 | 推理→工具调用→观察→再推理，有上限 | ⑦ |
| W3 工具调用协议 | JSON Schema 声明 + 执行 + 回填 | ⑥ |
| W4 流式协议 | SSE 逐 token，`data:…\n\n` 分帧，跨块缓存 | ②⑤ |

## 3. 关键抽象与端口

### 3.1 端口定义（核心层对外部实体的封装）

| 端口 | 文件 | 职责 | 适配器 |
|---|---|---|---|
| ① 多模型适配 `IModelProvider` | `model_provider.hpp` | `chat/stream` 统一接口，OpenAI JSON ↔ 内部类型 | `providers.cpp`（OpenAIProvider / MockProvider） |
| ② 传输 `IHttpTransport` | `http_transport.hpp` | 发送请求、流式回调字节 | `http_winhttp.cpp`（WinHTTP） |
| ④ UI `IUIPort` | `tool_registry.hpp` | `confirm()` 阻塞询问 / `notice()` 单向通知 | CLI / 无头 `NoUI` |
| 权限 `IPermissionGate` | `tool_registry.hpp` | deny/ask/allow 判定 | `DefaultPermissionGate` |
| 插件宿主 `IPluginHost` | `plugin.hpp` | DLL 发现、加载、ABI 校验、生命周期 | 宿主加载器 |
| 工具 `IToolPlugin` | `plugin.hpp` | C ABI 工具接口（execute/freeString） | sample_plugin.cpp |

### 3.2 契约层类型（L2 定义，L1 仅约定）

共享类型集中在 `types.hpp`：`Message`、`ChatRequest`、`ChatResponse`、`ToolCall`、
`ToolResult`、`Usage`、`RiskLevel`、`ChatChunk` 等；所有模块以它为唯一共享词汇表。

## 4. 架构决策记录（ADR）

### ADR-1 语言与工具链：C++17 + MSVC 手动 cl.exe 构建

- **背景**：课程要求 CMake + VS 2022/2026；但本机 CMake 对 VS2026 工具集识别有坑，
  PowerShell 又无法继承 `vcvarsall.bat` 环境；
- **决策**：主构建走 `build.ps1`（vswhere 定位 MSVC → 手动设置 INCLUDE/LIB/PATH →
  直接 cl.exe）；`CMakeLists.txt` 保留双轨；
- **后果**：构建稳、无额外依赖；代价是脚本需维护。

### ADR-2 网络层：WinHTTP 原生实现，不引第三方网络库

- **背景**：需要带流式回调的 HTTP；课程环境无包管理器（vcpkg/conan 不可用）；
- **决策**：实现 `IHttpTransport`，用 WinHTTP 手写（含流式读取回调）；
- **后果**：零第三方依赖、可控超时/重试；代价是绑定 Windows。

### ADR-3 JSON：nlohmann/json 单头文件（thirdparty）

- **决策**：头文件放 `thirdparty/nlohmann/json.hpp`，无包管理器；
- **后果**：构建离线可用；注意 `/utf-8` 与非法 UTF-8 消毒。

### ADR-4 插件边界：C ABI（extern "C"），不跨边界抛异常/传 C++ 类型

- **背景**：C++ name mangling / 异常 / 内存布局跨 DLL 不稳定；
- **决策**：`plugin.hpp` 定义纯 C ABI：`extern "C"`、`errOut` 传错、谁分配谁释放；
- **后果**：插件可被任意编译器构建；代价是需 ABI 版本号与防御性校验。

### ADR-5 权限与安全：deny-first 权限门 + fail-closed + DPAPI 密钥

- **决策**：规则求值 deny 强制优先（stable_sort 置顶）；无 UI/无规则默认拒绝；
  密钥经 DPAPI 加密后才落盘；
- **后果**：安全默认；代价是误杀需人工放行（Ask）。

### ADR-6 上下文结构：顺序即缓存前缀

- **决策**：稳定内容（system/tools）固定最前且顺序不变，动态内容靠后；
  压缩以"追加摘要消息"实现而非改写历史前缀；
- **后果**：最大化前缀缓存命中、省成本降延迟；代价是历史只能追加式维护。

## 5. 关键数据流

### 5.1 一次对话请求（L3）

```
main.cpp ──ChatRequest──▶ IModelProvider(OpenAIProvider)
                              │ toRequest → JSON
                              ▼
                        IHttpTransport(WinHTTP) ──SSE 字节流──▶ StreamCtx
                                                              │ SSEParser 分帧
                                                              │ dispatchOpenAI → ChatChunk
                                                              ▼
                                               Renderer 渲染（流式输出）
```

### 5.2 工具调用循环（L4-L5）

```
for round in 1..N:
  组装 ChatRequest（system + history + tools） → provider.stream
  若 toolCalls 非空:
     逐个 dispatch（查表 → Schema 校验 → 权限门 → invoke → 消毒/过滤）
     结果作为 observation 回喂历史；continue
  否则: 输出最终回答，break
```

## 6. 技术选型与工程化

| 项 | 选择 | 理由 |
|---|---|---|
| 语言标准 | C++17 | 课程基线；MSVC 支持成熟 |
| 构建 | build.ps1（cl.exe）+ CMakeLists 双轨 | 见 ADR-1 |
| JSON | nlohmann/json 单头 | 见 ADR-3 |
| HTTP | WinHTTP | 见 ADR-2；Windows 原生、支持流式 |
| 日志 | 结构化文本（后续 JSONL） | 低成本可观察 |
| 测试 | MockLLM 假服务端 + PowerShell 回归脚本 | 无 API 花费、可重复 |
| 配置 | 环境变量 + 后续配置文件 | 简单可覆盖 |
| 持久化 | 后续 SQLite | 课程要求 |

### 6.1 目录结构

```
src/            # 主体源码（按 L2 契约拆文件）
tests/          # mock_server.py、verify.ps1 等
scripts/        # 构建辅助脚本
thirdparty/     # njohmann/json（不提交可下载，本地提供）
docs/           # SRS / HLD / SDD
build/          # 构建产物（gitignore）
```

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| VS 工具链不匹配（VS2026 vs MSVC 2022 套件） | 装 2022 兼容包；脚本报可读错误 |
| 中文路径（GBK）污染 | 宽字符 API + sanitizeUtf8 + `/utf-8` |
| 模型 API 不稳定 / 费用 | 默认 MockLLM；真实 API 环境变量切换、Flash 版 |
| 上下文超预算 | 降级链 + 消息守卫（L5） |
| AI 生成内容需验收 | 小组逐讲评审、verify 回归 |
